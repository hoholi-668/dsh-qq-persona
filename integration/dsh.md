# 接进 DSH

DSH 会自动注入 `AGENT.md`（工作区一份 + `~/.dsh/AGENT.md` 一份）。
想让它生效，最简单的方式是把规则拼进 `AGENT.md`。

## 方式一：拼进 AGENT.md（最简单）

```bash
cd ~/.dsh
cat >> AGENT.md <<'EOF'

# 群聊说话规则
（把本仓库 template/02 ~ 04 的内容粘在这里）
EOF
```

**注意**：`AGENT.md` 会注入到每个会话。如果只想让群聊会话生效，
用方式二。

## 方式二：做成 preset（推荐）

DSH 的 preset 是按场景切换的提示词包。给群聊单独建一个：

```yaml
# ~/.dsh/presets/qq-group.patch.yml
- id: qq-group
  name: '群聊人格'
  prompt: |
    （这里是 01-identity + 02-group-rules + 03-speech + 04-blacklist 的拼接）
```

然后在群聊会话里切到 `qq-group`，私聊用默认。

## 方式三：塞进角色卡文件

如果你已经有自己的角色卡（如 `AGENT.md` 里写了「你是谁」），
把 02~04 三段**追加到角色卡后面**即可，不需要合并。

顺序建议：

```
1. 你是谁（01）
2. 群聊铁律（02）   ← 最靠前，比人设重要
3. 说话方式（03）
4. 黑名单（04）
5. 认人分档（05）
6. 示例（06）
7. 边界（07）
```

---

## 验证生效的方法

1. 开一个新会话，问它「今天好累」——看回复是否 ≤10 字、是否没有「注意休息」。
2. 让它说「来点推荐」——看它是否拒绝/装傻。
3. 给它看一句群友互怼的话，看它是否插嘴。

**三条里有一条不对，就是没注入成功**（或规则被后面的提示词覆盖了）。

## 常见坑

| 坑 | 现象 | 解决 |
|---|---|---|
| 规则放在人设后面 | 模型被人设带跑，又开始写小作文 | 规则放**最前面** |
| 同时有多个 AGENT.md | 两份冲突，行为随机 | 只保留一份权威的 |
| 规则太长 | 模型只记住前几条 | 把 02 的 18 条压缩到 10 条以内 |
| 没写黑名单 | 还是「首先/其次」 | 04 必须放 |
