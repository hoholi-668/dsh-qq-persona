# 接进 qq-bridge（或其它 QQ 桥接）

桥接类项目的提示词通常由几段拼起来：人设 + 场景规则 + 时间/上下文。
这套规则应该插在**场景规则**那一层，不是人设那一层。

## 找注入点

在桥接源码里搜这些关键词，一般就能找到拼接提示词的地方：

```bash
grep -rn "buildPrompt\|systemPrompt\|system_prompt\|prompt.*+=" src/ | head
```

典型结构：

```js
const prompt = [
  personaCard,        // 人设（你是谁）
  groupRules,         // ← 把这套规则放这里
  contextBlock,       // 时间、最近消息、记忆
  taskLine            // 这一轮该做什么
].join('\n');
```

## 推荐拼法

```js
const GROUP_RULES = `
【群聊铁律】
1. 一条消息 1~10 字，不用句号，不列点，不总结
2. 被怼顶回去，不解释、不找补
3. 群里不是每句话都是对你说的，先判断指向谁
4. 不有求必应，可以装傻、已读乱回
...
【黑名单】首先/其次/希望这个回答对你有帮助/作为AI/辛苦了注意休息
`;
```

**要求**：

1. 规则放在**人设之后、上下文之前**——太靠后会被上下文冲淡。
2. **黑名单必须显式列出**，别写「不要像客服」这种模糊要求。
3. 如果用「分条发送」机制，规则里要写清「一条消息一件事」，
   而不是让模型自己决定分不分。

## 与调度逻辑的关系

这套规则只管**说什么、怎么说**；**什么时候说、说给谁**属于调度层。

两者配合的建议：

| 场景 | 谁会说话 | 规则 |
|---|---|---|
| 主对话对象发言 | 必回 | 100% |
| 熟人插话 | 看情况 | 衰减（见 conversation-pacing） |
| 陌生人 / 路人 | 大概率不回 | 只在被点名时回 |

**只改提示词、不改调度**，会出现「话变短了，但还是在每条都接」——
这时候需要调的是调度，不是语气。

## 常见坑

| 坑 | 现象 | 解决 |
|---|---|---|
| 提示词太长 | 后半段被忽略 | 规则压到 1500 字以内 |
| 每轮都重新注入全部规则 | 成本高、模型麻木 | 规则只在会话开始时注入一次 |
| 规则与工具说明混在一起 | 模型分不清「说」和「做」 | 分开两段：「说话规则」「工具用法」 |
| 没有「不要每条都回」的规则 | 刷屏 | 02 第 7、12、13 条必须有 |
